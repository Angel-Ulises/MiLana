# T11 — Hosting y alternativa preparada

Fecha de revisión: 14/09/2026.

## Decisión

No se cambia dominio ni DNS en esta entrega. No existe acceso verificado a la pantalla privada de facturación que permita afirmar qué plan de Vercel tiene hoy el proyecto.

La condición de salida es simple:

- Si `mi-lana-pn2f` está en **Vercel Hobby**, no se debe usar ese plan para una operación comercial: la página de precios y los términos vigentes de Vercel describen Hobby como personal/no comercial.
- Si el proyecto ya está en un plan de Vercel compatible con uso comercial, T12 no se activa solo por preferencia técnica.

Fuentes Vercel:
- https://vercel.com/pricing
- https://vercel.com/legal/terms

## Alternativa preparada: Cloudflare Pages Free

Para la aplicación estática actual, Cloudflare Pages admite integración con GitHub, despliegues por rama y vistas previas de pull requests. La documentación vigente muestra para Free 500 builds/mes, un build simultáneo, timeout de 20 minutos, hasta 20,000 archivos y 25 MiB por archivo.

Fuentes:
- https://developers.cloudflare.com/pages/configuration/git-integration/
- https://developers.cloudflare.com/pages/platform/limits/

Configuración prevista para MiLana:

- Repositorio: `Angel-Ulises/MiLana`
- Rama de producción: `main`
- Comando de build: `npm run build`
- Directorio de salida: `dist`
- Sitio: estático; no requiere base de datos ni backend para las calculadoras actuales.

## Qué validar en una URL temporal antes de cualquier cambio de dominio

1. `/`
2. diez rutas `/calculadoras/<slug>`
3. tres rutas `/situaciones/<slug>`
4. `/sobre`, `/metodo`, `/contacto`, `/privacidad`, `/financiamiento`
5. `sitemap.xml` y `robots.txt`
6. una URL inexistente debe responder como 404 y no servir la portada
7. imágenes responsive y fuentes
8. canonical debe seguir apuntando al dominio público `www.milanaaqui.mx`, no a la vista temporal
9. no cargar Analytics/AdSense en la vista previa

## Reversión

No se tocará el dominio hasta que la URL temporal pase la comparación. Antes del cambio se documentarán los DNS actuales y cualquier registro de correo. Si la nueva plataforma falla, la reversión consiste en restaurar los registros previos, no en mover el registrador.
